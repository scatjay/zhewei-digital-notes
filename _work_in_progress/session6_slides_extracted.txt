【第6頁】
提示詞
• 直接與AI對話，會難以受，因此會給予提示詞。
• 向LLM提出的問題，系統自動加入許多使用者不知道的內容來優
化LLM的回答，使其能達到使用者想要獲得的答案。
• 提示詞：系統提示詞、用戶提示詞
• Prompt太模糊，以至於LLM不知道該怎麼做出你想要的回答
• System Prompt：由開發者在後台設定的規則和人格設定。例如：
角色、性格、背景知識、語氣…等等。只要不是使用者直接說出
來，而是事前預設的設定。System Prompt會在每次對話時，自動
發給AI去運算User Prompt：用戶直接說出的設定或命令。問AI問
題->關鍵在於如何提出好問題 
• 系統自動加入許多使用者不知道的內容->隱藏提示詞 / 預設提示詞

提示詞工程Prompt engineering
• Prompt給LLM的問題 
• Prompt太模糊，以至於LLM不知道該怎麼做出你想要的回答。
• 把Prompt 寫得更精確，變得很重要 -> 所以語言能力很重要，要求
精確表達的語言能力-> Prompt Engineering
• System Prompt = 人設和做事規則 = 開發者在後台進行配置
• User Prompt = 具體任務 = 使用者自己輸入
• System Prompt =我是一個蔣中正的歷史研究者，請不要直接給出答
案，要一步一步具有邏輯的推理，並且必須要有史料作為證據。
• User Prompt = 蔣中正喜歡吃什麼？

【第10頁】
上下文工程 
•LLM本身沒有記憶。每次給它的消息，都是全新、獨立的
請求。
• 然而沒有記憶，就無法形成對話。
•使用者–Agent–LLM
• Agent會記錄使用者和LLM之間對話的歷史紀錄 
•Agent收到消息時，會將消息附加上過去的歷史紀錄，一起
發給LLM
• 因此讓使用者感覺到LLM似乎有記憶。
•這些歷史紀錄就稱之為上下文Context
• 如何管理這段歷史紀錄的技巧，稱之為上下文工程

【第13頁】
AI Agent
• AI Agent內部具有事先寫好的程序，例如：read、write、list
用來讀寫檔案I/O操作的函數
• AI Agent會將使用者的提示詞連同這些函數整合起來，如此
寫成Prompt，在發給LLM。
•LLM得到這個Prompt後，根據Prompt內容生成一篇具有調
用函數指定的文本
•如此一來AI Agent根據這篇生成文本調用並執行函數，就能
執行修改檔案的操作。
• 因此LLM就可以控制電腦幫你做到任何可以透過程式執行
的工作

【第14頁】
LLM本質上是機率生成
•因此AI Agent在收到LLM生成文本時，diff中引
用的原始程式碼是否與當前文件相符。
•如果不相符，說明LLM誤解了上下文。那麼AI 
Agent就會讓模型重新生成。直到一致為止。
•這麼一來，就可以確保LLM修改的對象，確實是
使用者正要編輯的檔案。
•因此Vibe Coding就能夠成為相對穩定可到的程
式設計工具。

【第16頁】
MCP=模型上下文協定
• 每個不同的LLM，他們的工具接入平台都不相同，為了統一，因此有了模型上下
文協定Model Context Protocol
• 通信協議 將通用工具 統一起來託管，稱之為模型上下文協定Model Context
Protocol
• 例如：web_brouse 網頁瀏覽
• 運行通用工具 稱之為MCP Server
• 調用通用工具 稱之為MCP Client，通常是 AI Agent
• MCP Server -> 通信格式/通信接口 ->MCP Client
• 除了服務 也可以提供數據 稱之為 resources
• 提供 Prompt模板的 稱之為 prompts
• MCP Server 可以和AI Agent 放在同一台電腦之中，透過標準輸入輸出進行通信
• 也可以佈署在網路上，透過Http進行通信
• 它與AI沒有關係，只負責幫助Agent 管理工具、資源和提示詞

【第23頁】
例如：女朋友說肚子餓了
• 問AI Agent (=MCP Client) “女朋友說肚子餓了怎麼辦 ”
• AI Agent會將問題放到 User Prompt
• AI Agent透過MCP Server獲取所有MCP工具的訊息
• 將訊息轉化成System Prompt或者是Function Calling 格式
• 然後連同User Prompt 一起打包起來丟給LLM
• LLM發現有個 “瀏覽網頁”的MCP工具，於是生成具有函數調用格式的文本給AI 
Agent
• AI Agent收到LLM生成的文本後，透過MCP協議調用MCP Server中 “搜尋網頁”的
工具
• “搜尋網頁”的工具訪問指定網站後，將內容發送回給AI Agent
• AI Agent再轉發給LLM 
• LLM根據網頁內容，最終生成答案： “吃麥當勞”
• AI Agent再將結果提供給使用者

【第24頁】
Agent Skill
• 將工作流程(個人化的工作流程)，以文本的方式書寫(根據特定格式)，稱之為Skill，並且
透過Agent調用，這一連串的流程 稱之為Agent Skill
• 簡單說：給Agent 看的 說明文檔 以Markdown格式書寫
• 分為元數據層 + 指令層
• 元數據層：說明文檔的封面、描述他的功能、負責的工作，至少有Name + Description
• 指令層：不做具體要求，只將事情說明白，如：執行目標、判斷規則、輸出格式、範例
• 以MD書寫，並帶有 METADATA 進行分類的 Prompt
• 當要求符合該MD的METADATA 時，才將符合的Prompt 傳送給AI
• 為了方便管理、避免浪費token，因此又在每個Skill中進行區分
• 為了調用工具，也可以在其中加入py執行檔和CSV表格
• 為了更精細化，可以在 Skill 拆解工作流程，讓AI按照流程進行工作
• 將Agent Skill 存放在特定的目錄結構裡 Skills  (連同工具的程式碼)
• LLM會根據預設的資料夾中，讀取Skill，將Skill放入Prompt中進行提問，以及根據Skill
調用工具

•Gateway才是整個系統的控制中樞

【第41頁】
Gateway的輸入
• 1. 人類傳達的訊息：不同工作區內，訊息是各自獨立的。訊息不會被跳過，但需要排
程，先後順序進行管理。
• 2. Hearbeat 心跳：每30分鐘，系統自動傳送訊息給OpenClaw。這段指令可以去檢查
信箱有沒有緊急郵件、有沒有預期任務、或追蹤待辦事項…等等，它會自動通知。計
時器是可以改配置 。
• 3.Crons 排程：指定精確的時間點，執行某種任務。
• 4. Webhooks外部系統通知：例如Email收到訊息，就會傳Webhooks給OpenClaw進行
處理。自動回覆數位生活中的事情，並且透過預設規則進行處理。
• 5. Hooks 系統內部狀態改變時，自動觸發。讓OpenClaw自我管理
• 6. Agent to Agent：OpenClaw之間的訊息交換。支援多Agent設定，讓Agent有獨立的
工作空間，又可以相互對話，不互相干擾。
• 上述設計，讓OpenClaw成為自動自發的AI Agent ->這讓OpenClaw看起來很像額外聘
用的實習生。

【第44頁】
舉例：教授催繳期末報告的E-Mail
• 教授晚上十點寄信給你，要你趕快繳交期末報告
• OpenClaw收到後，發現是教授寫的信，因此讀取內容
• OpenClaw根據內容發現很緊急，並抽取摘要
• OpenClaw調用通訊軟體，告知上述訊息。
• 你收到訊息後告訴OpenClaw，請幫我生成期末報告，題目是：XXXOOO。(這甚至可以跳過)
• OpenClaw收到後，蒐集教授資訊，理解偏好、查看之前的信箱，理解期末報告的要求和方向。
• OpenClaw基於上述資料，透過瀏覽器收集相關資料。甚至接通資料庫查詢相關史料，並下載。
• OpenClaw下載後，自動OCR手稿史料，儲存成MD檔筆記。
• OpenClaw根據網站內容和相關著作，理解當前研究趨勢
• OpenClaw根據教授偏好、史料、當前研究趨勢…等等，生成文章。再根據MD檔筆記，為文章加
入可驗證的註解。
• OpenClaw生成期末報告，並寫信給教授，由於即將預期，因此生成文情並茂的道歉信，並說明
期末報告仍有不完美之處，請教授多多指教。
• OpenClaw調用你的Email權限，附上期末報告和道歉信，於期末報告期限前寄出。
• 這段期間，你都在睡覺。教授收到信，誤以為你熬夜完成，頗感動，內容有史料、有文獻回顧、
有關懷現今研究，又有引用註解。同時又有道歉信。感動，加分~~~。
