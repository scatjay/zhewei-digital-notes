人文科學的研究邏輯，四點

A

研究對象的個別性。老師舉的例子：如果按自然科學邏輯，要有一千個蔣介石， 統計分析之後跑出來的數據才叫「蔣介石」；但全世界只有一個蔣介石， 人文研究對象都是個別的，不可能重複出現。

B

研究者的自身經驗。我們必然透過自己的經驗跟文化脈絡去解釋過去。

逐字稿舉例
「我們對於『民主』這個概念的想法，台灣可能跟中國大陸就不太一樣…… 我們看到中國大陸寫『民主』這兩個字，跟台灣人寫的雖然是同樣兩個字，它的核心概念一定不同。」
C

意義來自共鳴、來自連結。老師舉自己的研究：因為做近代史， 看到跟自己研究時代相近的東西（例如「楊維真教授的研究」）就更有連結、更有意義； 但這不代表沒連結就沒意義，只是對個人來講的意義不同——老師自己說對荷蘭時代台灣史接觸就比較少。

D

主客合一的客觀精神。人文研究追求的不是一個純粹客觀的東西， 而是主觀涉入之後的客觀見證——「人文科學本來就不是資料的堆砌，也不是模型的分析， 這跟AI的根本原理是有很大不同的」。

老師接著補了一段對後現代批判的看法，自己形容是「張飛打岳飛」——他認為後現代批判從來不是在批判 探究歷史事實的歷史學本身，而是批判自黑格爾哲學以來對單一主體性的霸權宰制；基於史料辯證為前提的歷史學， 本身就具有科學性，「如果基於史料辯證為前提的歷史學不被認為是科學的話，那麼從康德的視角來看， 從物理學以降的所有科學，都不具備科學性了」。

傅斯年〈中央研究院歷史語言研究所工作之旨趣〉（1928年，投影片原文）： 「史學只是史料學」「讓史料自己說話」，利用社會科學理論和方法來處理史料—— 老師由此主張歷史學的科學性根本，落在史料的可驗證性、可追溯性、可糾錯性三點上 （投影片p68三詞原文）。
02 — 電腦與人

電腦的本質，以及AI取代不了的三件事

運算流程（投影片p71）：問題 → 拆解成複雜數學運算 → 拆解成簡單數學運算 → 二進位運算 → 交給邏輯單元運算，再反向推演出答案。老師的結語：「它展現出來的看似人一般的智慧， 其實都是用計算模擬出來的結果」「只要有辦法跟電腦溝通，電腦就是反過來，從邏輯單元的運算， 一步一步推演出去，最後給你答案」。

靈感與創見AI只會在自己的運算框架裡繞，突破只能由人給的新資料、新想法帶來
共鳴寫作如何跟別人產生共情，這件事AI做不到
脈絡化理解從個人自己出發去理解一個文本、再轉譯給當代的人， 這是電腦沒有辦法做的事
老師的樂觀論點：「AI反而是人文再興的一個可能」——過去要花十幾萬找工讀生寫網頁前端， 或投入大量時間精力做一款歷史遊戲，「現在不用了……只要把自己的想法描述出來，它就可以變成一款簡單的歷史遊戲」； 但老師也點出反面：資工的人拿到我們的東西變簡單了，「他們要理解我們，還是一樣困難」—— 人文因此反而變得更重要，「但最重要的東西還是思考，就是思考」。

01 — 從手稿到一則筆記

史料進到 Obsidian 的實際流程

投影片第58-88頁示範的實際操作順序——這不是抽象講法， 是他真的一步步點給大家看的動作。

1. 新增「手稿解讀」資料匣，把手稿資料匣拖拉進去

先建立容器，再把原始材料放進來——資料夾結構本身就是第一層分類。

2. 在資料匣中新增新筆記，為筆記命名

一則筆記對應一份史料（或史料的一個段落），命名要能讓自己半年後還認得。

3. 筆記第一行寫 ---，開啟YAML區

這是「正文前頁」，專門用來賦予這則筆記元資料（Metadata）—— 人事時地物、出處、建檔人都寫在這裡，不混進正文。

4. YAML區裡也能用 [[ ]] 連結其他筆記，再賦予同義字

同一個人事物在不同史料裡可能有不同寫法，同義字讓搜尋/鏈結不會斷掉。

5. 用 Transkribus 或直接用 ChatGPT 做手稿辨識

Transkribus 底層是卷積神經網絡（CNN），專門辨識手寫古文書； ChatGPT 則是直接把手稿影像丟進去問。兩條路都示範過。

6. 「請根據你的判斷修改成正確的文章」——人工校對AI辨識結果

AI辨識不是終點，最後一定要人核對過——這句話是投影片原句， 是這整套流程裡唯一「不能交給AI」的一步。

04 — 卡片盒筆記法（盧曼 Zettelkasten）

四層筆記，從靈感到一篇完整文章

→
文獻筆記史料解讀／文書筆記／元資料， 讀一手或二手材料時的想法
→
永久筆記凝聚出的具體想法， 用自己的話寫、不是抄

寫「永久筆記」的三個原則

A

用自己的話寫，不要抄。每一則永久筆記都以最精簡的方式寫到最完整的短文。 如有引用，用雙向鏈結跟文獻筆記連在一起，不是複製貼上。

B

思考與其他永久筆記的關聯性，用編號體系記下脈絡——這是樹枝狀的體系， 不是流水帳。

1. 我中午要吃什麼好呢？

1.2 或者可以吃炒飯（1.1和1.2是平行關係，都在探討同一個上層主題）
C

每次寫卡片都要前後左右看一看，就能知道之前思考的脈絡是什麼—— 永久筆記不是孤立存在，寫的當下就在跟舊筆記對話。

01 — 提示詞工程

「把話講清楚」為什麼會變成一門工程

第四場整場沒有教怎麼寫提示詞——但p11那張圖已經把它要解決的問題畫完了。至於定義，要到第六場p9才出現。

要理解提示詞為什麼是個問題，先回到第一場老師講電腦本質的那一段。他整段都在否定電腦像人：

第一場逐字稿原話（p72）
我們知道電腦的本質，就跟我們以前用的計算機是一樣的道理：它可以算得很快，很會算，但它只會算，它是一個口令一個動作，不太容易舉一反三，也不太體貼，它沒有溫情，只有散熱的問題，也沒有感受。它展現出來的看似人一般的智慧，其實都是用計算模擬出來的結果。

「一個口令一個動作、不太容易舉一反三」——提示詞工程整門學問就長在這句話上。既然它不會舉一反三，口令怎麼下就是全部的功夫。（延伸比喻，非老師原話）這跟我們對學生交代作業是同一回事：交代得含糊，收回來的東西就會離你要的很遠，而且它不會反問你。

四個容易誤會的地方

術語常見誤解實際是
提示詞 Prompt泛指你跟AI講的每一句話第六場p6只分兩層：System Prompt＋User Prompt；一句話總結是「怎麼問」（第六場p30）
上下文 Context跟提示詞是同一件事第六場p3：提示詞＋系統提示詞＋對話歷史＋當前輸出＋工具列表，全部一起送出去；一句話總結是「怎麼記」（第六場p30）
System PromptAI的個性開發者在後台設的規則與人設，你看不到，但每次對話都在（第六場p6、p9）
溫度 Temperature調準確度給機率較低的字詞較高的機會；越高隨機性越強（第四場p113）
Top-K調回答長度只從機率最高的前K個Token裡挑；K＝1就是每次都選最高的（第四場p114）
為什麼它會胡說，答案在第四場：投影片p33一句話定了性——「LLM 大型語言模型，本質是文字接龍、一個龐大的數學函數」。p110示範得更直白，老師拿自己的名字接龍：「我是 → 解碼器 → 哲維92%、老師0.01%」。它每一步都只是在挑下一個字的機率，溫度跟Top-K就是在調這個挑法。第五場p4會列出LLM的五個侷限並收在「→容易產生幻覺問題」，p5再回頭指一句「為什麼會有這些侷限？→ 來自於LLM的底層原理」——指的就是這裡。
02 — 函數調用 Function Calling

讓AI真的動得了手的那一道手續：把工具寫成它讀得懂的格式

第六場p11只用一張投影片講完它。但要理解它為什麼非有不可，得先回到第一場那句「它只會在自己的框架裡面繞」。

第一場逐字稿原話（p73）
你想，它本質就是大量的運算，如果大家知道數學運算的過程就會知道：如果沒有新的東西給它，它算來算去，只會趨近於什麼？它只會在自己的框架裡面繞，不會有突破——突破只能由人所創造出來的新資料，或人不同的思考想法給它，它才有辦法突破既有運算演算法的框架。

函數調用要解的就是這件事：怎麼把框架外的東西遞進去。做法很土——把「我有哪些工具、每個工具叫什麼、要給它什麼參數」寫成一份固定格式的清單，跟你的問題一起送給AI。第六場p11的原例只有三行：

投影片p11原例（投影片原樣如此，缺一個逗號跟最外層的右大括號）
{ “name”: “list_files”,
  “desc”: “列目錄”
  “params”: {“path”: “str”}

翻成白話：這個工具叫 list_files，它的用途是「列目錄」，你要給它一個叫 path 的文字。投影片p11原文的說法是：把「用自然語言描述的 System Prompt 和返回格式，進行標準化、統一格式和規範描述，例如以JSON格式描寫」——這些用JSON寫下來的規格，就叫 Function Calling。

最反直覺的一點：AI從頭到尾只是在產生文字

第六場p13把整條線拆開來，看完會發現一件跟直覺相反的事。AI自己從來沒有碰過你的檔案——它只是寫出一段「要呼叫哪個函數」的文字，然後由旁邊那個程式照著這段文字去執行。投影片p13原話：「LLM得到這個Prompt後，根據Prompt內容生成一篇具有調用函數指定的文本……AI Agent根據這篇生成文本調用並執行函數，就能執行修改檔案的操作。」

所以「AI幫我改了檔案」這句話嚴格說並不準確：AI只是生成了一段「要呼叫哪個函數」的文字，真正去執行的是另一個程式。下一節講的就是那個負責執行的東西。

它還順手做了一件像校勘的事：第六場p14說「LLM本質上是機率生成」，所以Agent收到那段文字之後，會先核對「diff中引用的原始程式碼是否與當前文件相符。如果不相符，說明LLM誤解了上下文。那麼AI Agent就會讓模型重新生成。直到一致為止。」——先比對再落筆、對不上就重來。這個動作跟第二場p85要我們把辨識的整個過程都複製進底稿檔案、再拿去跟原始圖片一個字一個字比對，是同一種紀律；差別只在一邊是機器對自己做，一邊是我們對史料做。

（延伸解讀，非老師原話：如果要在我們自己的領域裡找一個對應物，最接近的是第二場p94講的 metadata——「它能把任何兩個不同的實體，依照表格的方式，整理成一張非常大的表格」。先講好欄位，兩批資料才交換得了；先講好格式，AI跟工具才接得起來。老師沒有把這兩件事並排講過，這個對照是這裡加的。）

03 — AI Agent

研究流程六步驟，未來有可能交給它跑

第一場老師拆完歷史研究六步驟之後，說拆解的目的是為了流程化、系統化、進而自動化——Agent 就是那個「自動化」。技術上的定義在第六場p13、p18。

第一場逐字稿原話（p88）
當我們把步驟拆解之後，我們才有辦法把這個步驟進一步流程化、系統化，甚至未來透過 AI agent 的方式進行自動化，都變成是有可能的。

那六個步驟在第一場p86：知識的分類 → 快速記錄自己的想法 → 凝聚跟思考 →（數位的分析方法，老師說這步「有時候不見得一定會有」）→ 書寫 → 知識共享。Agent 要做的事，就是把這條你已經在跑的流程接手去跑。

老師自己的定義：工具列表就是LLM的感官與四肢

第六場p18用的是身體的說法，不是機械的說法：

第六場投影片p18原文
LLM 是無法感知或改變外界環境
如何解決 → 工具列表 ＝ LLM的感官／四肢
・讀寫文件內容　・查看文件列表　・運行終端命令
將LLM和工具整合起來，變成能感知和改變外界環境的智能程序，就稱之為 Agent

換句話說（延伸比喻，非老師原話）：LLM 本身是一顆關在盒子裡、只會算機率接龍的腦；Agent 是幫它裝上眼睛跟手的那層程式。第六場p13列的三個最基本的函數是 read、write、list——讀檔、寫檔、看有哪些檔。就這三件事，已經足夠讓它替你整理一整個資料夾的史料筆記。

一個Agent身上有四個零件

Memory 記憶分短期記憶與長期記憶。這裡要特別記住：第六場p10說「LLM本身沒有記憶。每次給它的消息，都是全新、獨立的請求」——記憶是Agent幫它記的，不是它自己有
Tools 工具投影片p21舉的例子有日曆、計算機、代碼解釋器、搜尋……也就是上一節那份函數清單
Planning 計畫投影片p21列了四項：思維鍊、子目標分解、反思機制、自我審查。白話說就是它會先拆步驟，做完會回頭檢查
Action 行動真的去執行。第六場p22另外給了一個模式名稱：Plan and Execute，先規劃再執行

為什麼歷史學門要在意這個東西

老師在第一場給的理由跟技術無關，是數位人文推了十幾年推不動的那個痛點：

第一場逐字稿原話（p14）
最困難的其實是文本分析工具，沒有學生願意一個一個去標註那些詞語……但是呢，隨著 2025 年年底，出現了一個非常重要的東西，就是 AI agent 的快速發展，我發現過去很難入門的數位人文工具，已經變得越來越容易使用了，因為那個標註的工作，你就不用自己標，AI 都幫你標好了。
誠實面：它很吵，而且很貴。第六場p19給了一個很具體的數字——當你只是輸入「你好」兩個字，真正送給LLM的資料有「89775字符 90K數據」，裡面塞了讀程式碼的注意事項、記憶與上下文的管理說明、怎麼使用Skill、當前運行的環境、各個子Agent的用途、各個工具的詳細描述。投影片自己下的結論是：「→ 消耗TOKEN、容易產生幻覺」。所以Agent不是掛越多工具越好。
還有一格它不能碰。第二場p85講完整套手稿自動化之後，老師立刻回頭踩了一腳：「所以整套流程做完之後，最關鍵的地方是在最下面：前面都只是史料的辨識，最後一定要留一個位置寫下自己的解讀……前面這些辨識的工作都可以讓電腦來幫忙，但最後這段解讀，一定是研究者自己在閱讀、建構資料的過程中累積出來的。」Agent 講得再厲害，這一格沒有變。
04 — MCP 模型上下文協定

換一家AI，工具接線要整套重做——這才是MCP要解決的事

第六場p16定義得很直接：「每個不同的LLM，他們的工具接入平台都不相同，為了統一，因此有了模型上下文協定」。這跟昨天上午你們把Obsidian資料夾掛進ChatGPT不是同一件事——那其實是等一下第五場RAG在解決的問題；這裡先把MCP自己要解決的問題講清楚。

第六場投影片p16原文
每個不同的LLM，他們的工具接入平台都不相同，為了統一，因此有了模型上下文協定 Model Context Protocol。
通信協議 將通用工具 統一起來託管。

白話講：工具（讀檔、查資料、連網……）只要照MCP這套格式寫一次，Claude、ChatGPT、任何一個支援MCP的AI都接得上，不用每換一家AI就重寫一套。協定的意思就是講好一套通信格式。

MCP Server投影片p16：「運行通用工具」。可以跟Agent放在同一台電腦裡透過標準輸入輸出通信，也可以佈署在網路上用Http通信；除了服務，也可以提供數據（resources）跟提示詞模板（prompts）
→
MCP Client投影片p16：「調用通用工具，通常是 AI Agent」。也就是上一節那個拿著條子去動手的程式
投影片p16最後一句要記起來：「它與AI沒有關係，只負責幫助Agent 管理工具、資源和提示詞。」MCP 不是一種AI、不會思考、也不會讓誰變聰明。它就是一份接線規格。
延伸對照，非MCP本身：昨天上午第一場最後那一步——把Obsidian的資料夾掛進ChatGPT專案、讓AI讀得到你的筆記——做的其實是另一件事：把你自己的資料餵給AI讀，這是「資料」的問題，不是「工具怎麼接」的問題，等一下第五場RAG會正式講。放在這裡對照，只是因為兩者都在解決「AI原本碰不到某樣東西」，容易混在一起，先講清楚界線。逐字稿原話：「把 ChatGPT 這樣一個 AI 平台，讓它去讀取我們寫數位筆記時的內容……這樣的話，你在 Obsidian 裡面做的所有東西，都有辦法在 AI 裡面讀到，然後幫你進一步處理。」（第一場p88）

老師在p17舉的例子，是一個歷史學者的例子

這一整頁投影片示範的問題是：「蔣中正在1937年12月做了什麼？請幫我整理可以使用的史料和著作，我要去哪裡找？」備好的工具有三個：定位工具、圖書館接口、檔案館接口。下面是投影片p17寫的流程，順序沒有改：

LLM思考 → 需要知道使用者的位置 → 調用定位工具

Agent 啟動MCP協定、調用工具、找到使用者的經緯度，再把經緯度交回給LLM。

LLM思考 → 這個問題需要查詢哪些圖書館／檔案館

Agent 檢索圖書館／檔案館，把結果返回給LLM。

LLM思考 → 使用者到圖書館／檔案館位置的路徑交通規劃

Agent 調用 Google Map 工具規劃路線，返回結果給LLM。

LLM 根據檢索結果＋路線規劃 → 生成最終答案 → 平台 → 使用者

投影片p17自己下的結論：「上述工作流程讓LLM可以有自主規劃能力＋自主調用工具 → AI Agent」。

值得注意的是，這條流程裡LLM沒有「知道」任何一筆史料。它做的事只有三件：判斷現在缺什麼、決定該叫哪個工具、把工具拿回來的東西整理成一段話。真正去查館藏的是接口，真正動手的是Agent。這也是為什麼第六場p16要特別強調 MCP 跟AI沒有關係。

接下來兩場都會再用到它：第五場後半（p55起）會在 CODEX 裡實際碰到 MCP 跟外掛；第六場會把 MCP 放回p5那張總地圖裡，跟 AI Agent、Agent Skill、函數調用、OpenClaw 擺在同一層。這一節看懂了，那兩場就不會卡在名詞上。
05 — Agent Skill

一份寫給AI看的說明書，其實就是把你自己的做法寫下來

第一場老師說「我們必須一定要跟會開發工具的人講說我們需要什麼」。Agent Skill 就是把這句話寫成一個檔案——而且用的是第二場你們已經學過的 Markdown。

第一場逐字稿原話（p14）
我們如何把工具變得更容易讓我們使用，或者更容易從我們自己的角度去參與這個工具的開發。當然我們不可能自己投入工具的開發，但我們必須一定要跟會開發工具的人講說我們需要什麼。

第六場p24給的定義是：「將工作流程（個人化的工作流程），以文本的方式書寫（根據特定格式），稱之為Skill，並且透過Agent調用，這一連串的流程稱之為 Agent Skill。」同一頁下一行更白話——「簡單說：給Agent 看的 說明文檔 以Markdown格式書寫」。

這裡有一個對歷史系特別省力的地方：Markdown 你們第二場已經學完了。第二場p32從一個井字號加半形空格開始教起，說它「就像我們用 Word 編輯不同階層一樣」。Agent Skill 用的就是同一套語法，沒有新的東西要學。

一份Skill分兩層

A

元數據層。投影片p24的說法是「說明文檔的封面、描述他的功能、負責的工作，至少有 Name + Description」。作用是讓Agent知道什麼時候該打開這份文件——「當要求符合該MD的METADATA 時，才將符合的Prompt 傳送給AI」。這一層存在的理由很現實：「為了方便管理、避免浪費token」。

B

指令層。投影片p24：「不做具體要求，只將事情說明白，如：執行目標、判斷規則、輸出格式、範例」。也就是把你平常怎麼做這件事講一遍：要達成什麼、遇到什麼情況怎麼判斷、最後要長什麼樣子、給一個例子。

投影片p24原文（同頁其餘幾條）
為了調用工具，也可以在其中加入py執行檔和CSV表格
為了更精細化，可以在 Skill 拆解工作流程，讓AI按照流程進行工作
將Agent Skill 存放在特定的目錄結構裡 Skills（連同工具的程式碼）

如果要找一個已經在手上的例子：第二場p85那套手稿處理流程——先辨識、把每一版結果都貼進底稿檔案、最佳化、翻譯、拿去跟原圖一個字一個字比對、最後留一格寫自己的解讀——那整套講出來的順序，寫下來就是一份Skill。第六場p24講的「個人化的工作流程，以文本的方式書寫」，指的正是這種東西。

它同時是一道界線，不只是一份說明。第六場p25：「執行能力給了AI行動力。Skill則是為AI指明了方向。AI就能在Skill設定的邊界中，謹慎使用執行的權力。」上一節我們才講Agent有了手可以改檔案；Skill 就是那雙手的行為準則。對我們來說這句話的份量在於：那個準則是研究者自己寫的，不是廠商預設的。

（老師在第一場p18其實已經發過一份了：他說範例資料夾的第二個資料夾，「是我自己寫的一個 AI Agent skill 程式的基本框架，也先下載下來就可以了」。當時沒有展開講，現在知道那是什麼了。）

「蔣中正喜歡吃水果」：向量化在比對什麼

這是老師在P12反覆用的例子，直接照他的說法走一遍：

意思不是AI「讀懂」了蔣中正喜不喜歡吃水果，而是「喜歡吃水果」跟「愛吃水果」這兩句話的向量距離很近，「1937年12月1日南京天氣晴」離得很遠——找的是語意上的鄰居，不是關鍵字。

04 — RAG的邊界

RAG不是萬靈丹：它幫得上忙的地方，跟它幫不上忙的地方

老師在P51親口說「RAG技術的出現，基本上還是AI技術的一種衍生應用」——這句話定了調：它是輔助，不是替代。這一節把起點節提到「口頭跳過」的那幾頁內容補回來，一起收在這裡。

逐字稿原話（第五場P51）
RAG也有它的缺陷，我剛剛有提到過。RAG技術的出現，基本上還是AI技術的一種衍生應用，它能夠輔助我們的研究與材料整理；如果你的文字內容很明確，其實可以搭配一個簡單的RAG系統來輔助研究。

投影片p51文字層上還有一個具體例子，講的正是第02節提到「切分」會出問題的地方——指代流失：

投影片p51原文
這會導致文章關鍵內容會被切斷、流失。例如：指代流失
我是蔣中正，我愛吃水果。→ 我是蔣中正 ｜ 我愛吃水果。
這會導致「我＝蔣中正」這樣的指代關係流失。

一刀切在句子中間，AI就不知道後面那句「我愛吃水果」的「我」是誰了。投影片上給的改進方向是「必須依據文本類型進行預處理」，並舉了一個歷史學的例子：「將蔣中正日記中提到我時，應可以假設為蔣中正本人的指代關係」——這正是第02節P10「歷史學適合按頁碼分片」背後在處理的同一個問題。

但最終問題意識的提出、證據的權衡、脈絡的辨識與歷史的詮釋，仍然必須由研究者自己負責。我們剛才思考的是：這項AI技術是否能強化我們的可驗證性、可追溯性與可糾錯性，這正是RAG技術對我們歷史學研究相當有幫助的地方——但它仍有其侷限。
回到第一場的那三個詞：「可驗證性、可追溯性、可糾錯性」是老師在第一場就提過的史學研究根本標準，投影片p54把它原封不動搬過來當作RAG這一整段的結論——判斷這套系統值不值得用，標準是這三個詞，不是「查資料方不方便」。
05 — 轉場：Codex是什麼

半場過後，畫風忽然一轉：AI開始會「動手」了

從P55開始，老師說「那我們接下來要回到Codex的部分——剛剛其實已經先提過一次了」。這句「回到」很關鍵：對老師來說這不是全新的話題，是把上午稍微提過的東西正式攤開來教。

Codex是ChatGPT底下的一項功能，屬於「AI coding agent」——不只回答問題，還能真的去讀寫檔案、執行程式。第一步不是打字問問題，是先讓它認識你是誰。

第一件事：寫一份「AGENTS」筆記，告訴它你是誰

逐字稿原話（第五場P59）
回到Obsidian，在根目錄底下建立一則新筆記，標題就叫「AGENTS」，下面可以寫你自己的描述，比如「我是某某某，是一名歷史學家，專攻什麼什麼歷史研究」之類的都可以。這個AGENTS筆記的作用，基本上就是預設你的人設，也就是預設一段基本的提示詞。

投影片畫面上，老師自己示範的那則筆記寫的是：「我是張哲維，一位歷史學家，專攻德國對華關係史」。設定好之後回到Codex問它「我是誰？」，它會自己去筆記庫裡找到這則AGENTS筆記，回答出正確的身分——第五場P62把這個操作定性為「上下文工程」的一部分：「AI就是透過我們的agents.md這個檔案，知道你的背景設定，回過頭來告訴你答案」，並預告「這都是上下文工程的一部分，我們下午才會講上下文工程的基本原理，現在先教大家怎麼操作」。

它能動手了，所以要先講清楚能動多少

P62接著講的是一個「核准」機制——這是Codex跟前面RAG機器人最大的不同：RAG只會回答問題，Codex可以真的去改檔案。

核准層級投影片／逐字稿原意
要求核准每一步執行前都先問過你才動作（第五場P62）
代我核准「只要不會導致系統崩潰、或造成權限外洩之類的情況，它就會自動幫你核准」——老師建議的預設選項（第五場P62）
完整存取權完全自主執行，「甚至有可能把你整台電腦搞當機，所以基本上我們用不到這個選項」（第五場P62）
為什麼要有這一關：「因為安裝了Codex（ChatGPT的這項功能）之後，理論上AI可以呼叫你電腦裡所有的資源，這是相當危險的一件事。」（第五場P62）核准機制就是這套風險的煞車。

模型選最便宜的，額度有上限

第五場P63提醒大家「不要選擇最好、最新的模型，選擇最簡單的那個就好，因為選擇最新的模型，Token消耗非常昂貴」。免費額度是分5小時一個週期計算，用完可以按「重置」，但「只能重置三次」，三次用完就只能等下一個週期——老師也提醒還有一層週額度：「這一週還有77%」，5小時的小額度用完之外，一整週也有總量上限，用完同樣要等下週——「這就是『有沒有花錢』的差別」。

第五場P65讓大家在Codex裡打一句話：「幫我寫一個簡單的井字遊戲」。投影片上實際錄下的回應寫著：「我會做成一個可直接在瀏覽器玩的簡潔網頁版，先確認目前資料夾結構，再依網站製作流程完成並測試」，下方還顯示一行小字「正在讀取 Sites Building 技能」——這正是後面第06、結語節會正式介紹的「Skill」，這裡先讓大家看它在背景被叫用的樣子，不用先懂。

System Prompt ＝ 我是一個蔣中正的歷史研究者，請不要直接給出答案，要一步一步具有邏輯的推理，並且必須要有史料作為證據。
User Prompt ＝ 蔣中正喜歡吃什麼？

p8老師示範了一個日常版本：ChatGPT的「個人化」設定，其實就是使用者自己動手寫System Prompt——「先跟它說你是一個怎麼樣的角色，比如說你是一個外科醫生，今天要幫某位老師動刀……這樣它就會假設自己是一個骨科醫生」（p8原話）。至於為什麼要把話講精確，老師的解釋很直接：「Prompt太模糊，以至於LLM不知道該怎麼做出你想要的回答……所以語言能力很重要」（p9）。

上下文工程、函式調用、Vibe Coding：AI Agent怎麼從對話變成能動手的東西

因為AI沒有記憶，如何幫它把對話紀錄管好，就變成「上下文工程」（p10）。接著人們把「工具列表」也塞進上下文裡，AI才知道自己能呼叫什麼、該用什麼格式呼叫——這叫Function Calling函式調用，全部用JSON格式描述「要怎麼呼叫、目錄在哪裡」（p11）。再往下，AI寫程式時靠的是Git版本控制裡累積多年的diff格式（記錄「哪一行被換成什麼」），因為這種格式訓練資料量夠大，AI寫起來才可靠，這就是Vibe Coding的基礎（p12）。老師把這些全部收在一起：「我們把前面講的 Function Calling 跟 Vibe Coding，還有這些工具全部整合在一起……稱之為 AI Agent」（p13），內部就是一組事先寫好的read／write／list這類讀寫檔案的函數。

老師自己的類比：當AI Agent生成的程式跟原檔對不上，系統會讓LLM重寫一次——「就像我們教學生一樣，如果一個學生作業寫失敗，你會叫他怎麼做？再寫一遍」（p14原話）。這是老師自己在課堂上打的比方：AI改稿的邏輯，跟老師要求學生重寫作業是同一件事——只是這個過程「相當消耗token」。
02 — MCP、Agent Skill、Harness

MCP、Agent Skill、Harness：把散裝的AI工具組裝成一套系統

有了工具、有了記憶管理，接下來的問題是：這些散裝的能力怎麼被組裝成一套穩定運作的系統？老師沿著MCP→Agent Skill→Harness這條線，最後在p30收成一句三段式的總結。

先講MCP（模型上下文協定）。老師用「連接檔案館」當例子，講得很白：

逐字稿原話（p16）
我們可以透過 MCP 去連接不同的資料庫……比如說你要查詢某個檔案館，你的帳號密碼可能已經先寫在 MCP 協議裡了，這樣兩邊連線之後，每次你問問題，它就會到那個檔案館，把帳號密碼輸入進去，取得許可權才能夠呼叫。

工具一多，代價就是資料量暴增。老師p19給了一個嚇人的數字：光是輸入「你好」兩個字，真正送給語言模型的資料超過90K字元——User Prompt本身、Harness的注意事項、記憶與上下文管理說明、如何使用Skill、當前執行環境、子Agent用途、每個工具的詳細描述，全部打包一起送出去（p19）。這也是為什麼老師在p20被現場老師問「能不能自己架本地端語言模型避開這些資安疑慮」時回答：「有可能，只要有錢都做得到……未來每個歷史系都有自己的一片H200晶片，就可以把運算搬進來」——但也老實承認，自架的服務品質「相信不會比現在用的ChatGPT更好」，因為商業公司的晶片與工程資源都更龐大（p20）。

AI Agent的基礎架構，老師自己畫了一張圖（p21）：記憶（短期／長期）、工具（日曆、計算機、搜尋……）、計畫（自我審查、思維鏈、子目標分解）、行動，四塊拼起來。「說真的我們自己做不到這麼細的程度，但知道它有這樣一個過程就可以了」（p21）——這句話是老師自己對聽眾程度的判斷，值得記住：這堂課的目標不是要人文學者自己寫這些底層架構。

一個提醒：AI幫你決定的事，背後可能有生意

p23的「女朋友肚子餓了」示範，表面在講MCP串聯多個工具的完整流程（搜尋網頁→呼叫Uber Eats→呼叫信用卡MCP付款），但老師花更多篇幅講的其實是另一件事：

逐字稿原話（p23）
為什麼一定是麥當勞？……這裡面有非常強的商業可能性——因為你要吃什麼東西，看起來是隨機生成的，但只要看起來隨機，就有可能是廠商置入……而且問題是，人本來就是懶惰的，反正它推薦什麼，我就吃什麼……全部交給AI決策，99%的人都會選擇交給它決策，因為我們都很懶惰。

這段不是離題閒聊，是老師刻意插在MCP講解裡的提醒：工具串接得越順手、AI幫你「自動決定」得越多，商業置入就越容易藏在看不見的地方。

Agent Skill與Harness：怎麼把流程寫下來、怎麼把整套系統管起來

Agent Skill，就是這兩天大家實際操作用到的東西——一份.md檔案，「把剛剛那一系列拆解的過程先寫下來……它每進行一步、要進行下一步時，就會回去讀一次Skill，知道下一步該做什麼」（p24）。老師特別補一句給這整套技術降溫：「你就會知道，這個過程看起來好像很厲害，其實說穿了也沒有多強，就是這樣子而已」（p24）。

再往上一層是Harness——把AI Agent這些零散元件系統化、讓語言模型「更符合規範……並且創造出一個以大型語言模型為核心、穩定運作的工作系統」（p26）。老師把這件事丟回給在場的人：「這些東西都是誰做的？都是商業公司，或者是某些工程師……我們人文研究有沒有辦法，設計出屬於自己人文研究的 Harness？」（p27）——這個問題投影片p27直接寫成「（人文研究專用的Harness？？？？）」，四個問號，目前沒有答案，是留給在場歷史學門主管的開放題，不是老師已經解決的東西。

老師收在p30的三段式總結（可以整節課倒回去對照）：「提示詞工程告訴我們怎麼『問』，上下文工程告訴我們怎麼『記』，而 Harness 工程告訴我們怎麼『管』——這是一系列發展的歷程」（p30原話）。老師也在p29補一句方向：「人的核心職責已經開始改變，變成要如何建立一個穩定可靠的系統架構」。
03 — 龍蝦解剖

龍蝦解剖：從OpenClaw看AI代理人的邊界與風險

老師接著用一個真實案例把前面的概念串起來：OpenClaw（老師戲稱「龍蝦」），一套讓AI透過手機、遠端操控你所有電腦的系統。這一節內部的技術細節，老師自己在課堂上明講「跳過」——這是他因應時間不夠的現場取捨，不是內容被忽略。

OpenClaw的設計者是Peter Steinberger，奧地利軟體開發者，2026年2月起在OpenAI工作（p33）。老師用自己實際安裝的經驗說明它在做什麼：

逐字稿原話（p36）
我自己的手機前陣子就請工讀生幫我安裝了 OpenClaw。比如說我走到戶外，看到台灣的寺廟有很多匾額，就把它拍下來，說『請幫我記錄』，它就會幫我把內容記錄到電腦裡；或者匾額上有些文字，請它幫我分析，它分析好之後，也能直接存到我的電腦裡。所以我透過手機，就能夠遠端控制我許多台電腦。

04 — 賢者之石

賢者之石：AI的本質與一場不可逆的典範轉移

進入結論前，老師先定調AI是什麼等級的變化，再用《鋼之鍊金術師》裡「以石頭核心製造出來的人」，講他心目中AI最根本的侷限——沒有情感、沒有歷史經驗、沒有道德感。

逐字稿原話（p51）
我一直認為，AI基本上是一場不可逆的典範轉移。而這樣的轉移，不只是理論上研究視野的轉向，而是更大、更全面、影響更深遠的變化，甚至對整個歷史學以及人文學界之所以稱為科學，從研究方法上重新定義，乃至於在人類整體知識中意義的重塑。當然，它既是危機，也是一個轉機。

接著老師提出五個數位人文基礎建設的優先方向（p52）：強化史料可驗證／可追溯／可糾錯性、建立統一資料結構與算力中心、從使用者視角強化UI設計、建立共同培育平台讓AI融入教學、強化研究成果推廣。第五點特別被他點名，理由很直白：「這四點每一項都需要錢，可是當我們沒有辦法跟社會大眾說歷史研究很重要的時候……有錢能使鬼推磨，那是真的」（p52）。

「以這石頭核心製造出來的人」——老師自己用的動漫比喻

這是這一場最鮮明的比喻，投影片p53、p54各截了一張《鋼之鍊金術師》的畫面：p53是老爹（Father）胸口的紅色核心，字幕「以這石頭核心製造出來的人」；p54是老爹自稱「你就叫我Homunculus（人造人）吧」的畫面。老師直接借這個角色講AI的本質：

逐字稿原話（p53–p54）
至於AI的本質是什麼……它是一個擅長分析、分類的深度學習系統，但它沒有情感，也沒有歷史經驗，更沒有道德感，這是一個很重要的問題。它就是以一顆石頭為核心創造出來的東西，用來記憶人類、記憶個體資訊——一種人類本身無法比擬的訊息量。所以我們其實不能夠直接把基於統計、大數據運算，以及自然語言分析為核心的電腦系統，直接套用到人文研究的教學上面，否則我們很容易失去方向，甚至失去人文的溫度跟深度。

換句話說：AI能吸納、記住遠超單一人類個體能負荷的資訊量，這一點像老爹靠賢者之石聚合了大量人類的靈魂與知識；但它終究沒有情感、歷史經驗、道德感——這正是老師整段課想提醒的：AI是強大的分析分類工具，不是能替代人文判斷的主體。

智慧人文：不是被動配合工具，而是回到人文自己的邏輯

老師提出「智慧人文」作為回應AI變革的理念（p57），核心是「回歸使用者的主體性，而不是讓人文變成被動、遷就既有現成工具的樣子，而是從人文科學本身的研究邏輯，以及實務的研究流程出發，再應用上AI技術」。這個理念底下有四個具體主張（p56-59）：歷史話語權是主權AI的根基、智慧人文回歸人文邏輯與研究流程、以智慧人文捍衛主權AI、以智慧人文發展產業鏈結。

關於第一點，老師的擔憂是具體的地緣政治想像：「如果未來中國大陸擁有這麼強大的大型語言模型、這麼龐大的資料……最後能夠留下來的，可能只剩中國大陸的AI系統。到那個時候，未來也許就不會再有『台灣』這兩個字，或者說『台灣』這兩個字，會被他們產生非常非常大的誤解」（p56）——這是老師個人對AI地緣政治的判斷，如實記錄，不代為延伸評論。第四點（產業鏈結）落地到教學現場，老師舉了自己姊姊的例子：「我姊姊的英文能力很差，但她教出來的小孩英文卻很強……她唯一做的事情就是盯著孩子、告訴他該怎麼做——這種『引導者』的角色是很重要的」（p59），用來說明AI時代教師的角色從「什麼都會」轉成「引導」。

投影片p60的視覺設計（已核對投影片畫面）：「算力」與「演算法」兩行被紅色刪除線劃掉，只留下字體最大、沒有劃掉的第三行「理解人的需求」。老師口語呼應這個設計：「未來技術的突破會在哪裡？不是算力，也不是演算法——算力是台積電的事情，演算法是數學家跟資工系的事情——我們唯一的工作，就是要理解人到底需要的是什麼」（p60）。

結尾老師又回到《鋼之鍊金術師》，這次是p61的畫面——一隻狼／犬與披斗篷的鎧甲騎士對望，字幕「對不起 以我們的力量沒法讓你復原」（畫面對應的是阿爾馮斯的鎧甲軀體與犬隻場景）。老師借這句台詞收束AI侷限性的論點：「AI工具本身的侷限性——它不能夠取代我們思考、情感、道德，以及個人的獨特性，更不能替我們做出決定。也就是說，AI其實不可能代替我們活著，只有我們親自去體驗這個社會、體驗這個當下，這才是人的價值之所在」（p61）。

05 — 具體怎麼做

具體怎麼做：從數位筆記到結構化資料的五個步驟

講完典範轉移的高度，老師收回到「具體該怎麼做」（p62）。這一節是投影片p66-75明確編號的五個步驟，從寫數位筆記開始，一路走到JSON、CSV、TEI，最後接上AI工具與RAG。

在講五個步驟之前，老師先把「為什麼歷史學需要資料基礎建設」講清楚，而且直接點名傅斯年：

逐字稿原話（p65）

老師的長期構想是收集人文學者「閱讀之後產生的想法」，而不只是資料本身：「不能只有資料本身，而是要記錄人們閱讀之後，能夠激盪出怎麼樣的想法」（p87），因為「人如何產生創意？如何產生靈感？如何產生想法？這可能是未來最重要的一個關鍵」（p88）。他也直白地說出這個構想背後的現實：把這些資料整理出來，就有機會「賣給Google，換取一大筆錢」，用這筆錢把系統做得更好（p89）；但同時強調AI做不到的地方——「表面的描述其實都沒什麼，AI只能讀懂表面的描述，但我們要如何理解語言之外、它真正想訴說的故事跟內涵？」（p89），這需要「很長的研究經驗、很深的歷史見識」。

最終目標，老師收得很簡潔：「歷史學家未來只要讀書跟思考、挖掘史料跟解讀史料、還有教學推廣跟社會對話，就可以了」（p90），並笑稱「這個目標說穿了就是懶惰」（p91）——但也強調三件事AI永遠取代不了：理解人的需求、由人產生的資料、基於人自身經驗產生共鳴才有意義（p91）。

謝謝各位師長、嘉賓。接下來的活動，我們將請本校人文社會AI應用與發展研究中心的林文源教授，來跟大家分享他對於AI時代下學術倫理的思考，有請林文源教授。

召集人、李卓穎院長，和各位主管，大家好。今天很榮幸來這邊跟大家分享一點想法，不過因為我身體狀況比較特殊，我就把口罩戴著，坐著講，節省一點體力。

那今天，本來大會指定我的題目是要談「學術倫理」，但是對這個議題，我有一點點小小的建議，所以我就稍微把它改一下，叫做「研究規範」。另外，自然科學跟人文社會的領域其實有一點差異，這部分之後有機會再談，所以我把範圍限定在人文社會這個領域。

一開始，這是我基本的背景資料。最近幾年，因為資源挹注的關係，我參與了幾個跟AI相關的方案，其中比較重要的一項，是跟我們學校的王道維老師合作——王道維老師之前也跟大家分享過非常多，他是真正在打造各種AI應用的人，我也跟大家介紹一下。然後我們新成立的中心，叫做「人文社會AI應用與發展研究中心」，這個中心我們累積了不少東西，有機會歡迎大家參考。

那我今天的內容，包括分成五個大部分，分別是：從「想像AI」開始，談研究跟倫理規範，一路到三個層次，最後是尋求協作者的一個想法。那我就開始，第一個是：對AI，我們到底在想什麼？

其實AI，如果大家還有印象的話，大概是2022年底，因為ChatGPT的關係，才開始迅速地變成人盡皆知的話題。但如果大家對AI的發展歷史有一點瞭解，其實從1950年代這個構想就已經開始，中間歷經了起伏、希望與失敗。最近這一波，看起來AI真的來了。

在它之前，也有一些小應用，大家可以看到，譬如說把它做成3D投影的樣子——這個你不能拿它跟現在的AI比，它看起來很拙劣，但它的確也是某種人工智慧型的應用，它可以跟你say hello等等，或者後來的機器人，一直到現在真正走動的機器狗，這些各式各樣的東西都出現了。

再來，另外一種想像的可能性，是我們也開始把AI想像成有可能在未來取代人，成為我們親密關係的伴侶。這些也已經有相關的法律，已經讓人跟AI結婚了，或是有人愛上AI等等，這些現在也已經不算是新聞了。另外一個想像是，大家也認為在高齡化、少子化的未來，人的各種孤單寂寞可能會需要更多的陪伴，由機器人來陪伴人這件事情，現在似乎也已經成真了。據說ChatGPT最重要的功能之一，現在是類似這種心理陪伴的功能，而且使用這個功能的使用者比例還蠻高的。

再進一步，前幾個月，當大家還在談論「通用型AI（AGI）」跟「特定型AI」的差別的時候，後來ChatGPT開始出現，大家發現AGI可能快要出現了，到了今年，「代理型AI（Agentic AI）」也開始出現了，所以大家對AI的想像又更進一步，它似乎可以開始全面進入我們的生活，不像之前那些單一方面的應用。這裡有一個蠻有趣的例子，是鋼鐵人——鋼鐵人裡面有一個萬能管家叫Jarvis，Jarvis這個名字其實是「Just A Rather Very Intelligent System」，意思是超級聰明的系統，我們今天回頭來看，它其實就是一個AI代理人。

到前幾天，從AGI的構想開始有一些曙光以來，就有各式各樣AI逃跑、AI作弊、AI串聯要反叛等等各式各樣的傳聞，有些看起來是商業的噱頭，但前幾天又出現三個科技巨頭——OpenAI，還有一些其他公司裡面的研究員等等——他們都出來再次呼籲說AI會毀掉全人類。這到底是不是事實，我們現在還不確定，但我的意思是，在這些不同的想像中，我們對AI能做什麼、不能做什麼，以及人類在這個過程裡面會變成什麼樣，這幾年我們大概每兩三個月就會歷經一波期望或焦慮。

那我想，今天這個大會其實非常有用心，剛剛跟卓穎院長還在聊，我這兩年一直在觀察，也受歷史學界幫忙很多——我在觀察國內哪些學術領域對AI這個進展比較投入，其實歷史學界是投入得非常非常快的一個領域，所以在學術領域，我們也同樣遇到了這樣的期待與焦慮。

一方面，我們看到AI對於科學研究做了很多以前非常困難、要花很多力氣才能做到的事情，譬如說解蛋白質結構，到前陣子又有一則喜訊，是AI解出了一個很困難的數學題目——這一波AI浪潮還會持續下去，所以在科學研究上，AI當然帶來了非常大的幫助。

另一方面，也是今天我們討論的主題：在過去，以人類為主的研究，對於倫理跟誠信這件事情是相當看重的，尤其是在人文社會領域，對於「個人化」的作者身份這件事情是很重要的。但AI來了，它看起來似乎可以幫我們代理非常多的事情。其實很多領域我觀察到，已經有人公開教大家怎麼用AI寫研究計畫、幫你找文獻、幫你寫研究計畫書，現在反過來也有人教大家「你不能用AI去審查這個計畫書」——這也還蠻有趣的，大家申請了一堆計畫書，我不能拿那些計畫書去審查它，我不能用AI來審查它，這件事情我想大家多多少少都有耳聞，我們甚至有親身經歷，因為我最近接到的幾個委託裡面，有一些明顯看起來AI的味道很重，這個已經是現實了，這在全球也是如此。

這是去年的一個統計，是「撤稿」的統計——論文通常是被發現有問題才會撤稿——大家可以看到，2022年底ChatGPT大量出現以後，2023年的撤稿率幾乎倍增，這是人類史上一個重要的現象，它很可能會改變人類對知識累積的一些看法。當然，更不用講，這個過程本來就已經加上原有的跨國移動等因素，現在再加上AI，這裡面又更複雜了一層。

所以在這些各種想像之中，今天我們就聚焦在：想像AI時代的研究跟倫理規範，這是我今天的任務。

那我基本的想法是，如果大家有稍微接觸過我的一些演講的話，我大概都把AI分成三個層次來看，或者說有幾個基本面向。那我今天就用「研究中的倫理規範」，分三個層次來跟大家分享我的看法：第一個是個別的工具層次；另外一個是作為科技與社會體制一環的基礎設施層次；另外一個是作為新的知識革命的層次。我就從這三個層次，來跟大家分享我的看法。

第一個，工具的層次，這件事情已經有非常非常多討論了。譬如說，這是2024年英國皇家學會的報告，他們提到，AI的確有機會在現在越來越複雜、越來越大量的資料集中，找到新的pattern跟關係，這個在聲音領域，或者像分子結構這些領域，已經展現出它非常重要的影響力，這對科學來說是一件好事。

但是，與此同時，他們也提醒大家——這也是我們今天關注的主題——AI跟研究領域的關係，我們要關注幾個面向。如果我們在研究中大量使用AI，第一個是它的「可驗證性」，大家知道，科學能不能被驗證、能不能被複製，是很重要的事情，要不然就很容易有造假的嫌疑，所以這是他們很關注的第一點。第二個是，他們認為在未來AI的時代，使用AI的領域跟被AI影響的各個領域之間的跨領域合作，將會越來越重要，這也是我們今天看到的一個重要趨勢，就像今天的會議。第三個是它的環境代價，大家或許有聽過，AI的所有運算力都不是免費的，需要大量的電，講得白話一點，它就是在耗電，所以現在AI的競爭，基本上是各種基礎設施的競爭，這些AI公司在拼命找地方蓋資料中心，更重要的是蓋電廠，所以這些AI公司幾乎都快變成能源公司了。

再來更重要的是，對於open science（開放科學）這個原則，中間的隔閡會越來越大——我們用了越來越多的AI，但AI的運算跟它產出的結果非常複雜，前面也提過，它到底是怎麼產生的這個結果，也就是可解釋性（XAI）的問題，AI有能力製造這個結果，但不一定能夠好好地說明這件事情。當然這不是我們現在已知、可以查證的事實，而是當它解出一個新的結構時，我們要花力氣才能理解它是怎麼解的，而科學是需要解釋的。

最後一個，可能是我們現在會越來越擔心的：當未來我們大量倚賴AI輔助研究，一個好的研究成果出來以後，我們會思考一個問題——這個研究者，是因為很會用AI，還是因為他研究做得好？大家可以理解這個意思嗎？就像電腦跟統計軟體出現以後，各式各樣的統計方法讓我們能夠處理一些複雜的事情，甚至有些統計學的研究方法本身，就是在討論各種統計問題跟數學問題。那未來當AI成為研究方法、融入各領域的時候，在方法論上，它到底算不算是研究者用得好，這是英國皇家學會關注的重點之一。

不過整體來說，他們還是鼓勵使用AI，但強調幾個重點：第一，希望各個機構能夠盡量普及AI，讓大家都能夠用到、也能夠適應AI；第二，希望大家能夠盡量遵守開放科學的原則，這跟剛剛講的科學的透明性與開放性有關；最後，他們強調AI的使用必須符合對公眾利益的倫理原則——這一點還蠻有趣的，因為如果從這個角度來看，他們談的並不是「學術倫理」原則，而是「對公眾利益的倫理」原則。這是我們現在看到的、還蠻有代表性的一個機構，對AI涉入學術倫理的看法。

另外，我也要小小地報告一下，我們中心——清大人社AI中心——我們先從教學指引資料庫、研究資料庫做起，現在已經蒐集了全世界五大洲、大概分成六個重要區域，一些重要機構的教學指引，我們從教學開始做，這裡面有一個資料庫，過一陣子會公布，請大家到時候再參考。

在工具層次，其實現在各個單位，你們隨便去查、或問AI，它都可以告訴你，這是一個比較容易理解的層次，不管是AI或倫理，拿它來做什麼事都算容易掌握。

第二個層次，如果我們把它從整個體制的角度來看：AI可以構成科技社會體制的一部分，這不用說，大家應該可以理解——它可以進入教育體制，也可以進入司法體制。同樣的道理，想要讓AI不管是乖乖聽話，還是好好為人類謀福利、促成公眾利益，各種倫理或規範，它也可以成為科技社會體制的一環，我想這也是我們今天要談的。

在這邊我想提一個技術與社會研究裡面的概念，叫做「科技社會想像力」，它的意思是，希望藉由這種想像力去探討AI的影響。我跟王道維老師，還有一起工作的一些夥伴，我們把它稱為「公共化AI」，基本上跟公共價值有關，不管是哪個領域——尤其是人社領域——對未來、對我們現在共存的狀態都會有一些想像，我們把它統稱為公共性的想像。尤其在這個過程裡，我自己習慣用「科技社會想像力」去想像AI的能與不能，藉此拓展我們的想像力，等一下的討論大概會跟這個有關。

所以，如果從體制的角度來看AI的科技社會體制，它就不只是技術了——技術當然重要，但絕對不只是技術，我想大家大概可以同意這一點。尤其民主社會都牽涉到多重利害關係，更重要的是要觀察AI牽涉的多重基礎設施，譬如我剛剛講的，因為AI發展，發現沒有電，所以現在開始蓋電廠，但蓋電廠不是一件容易的事，爭議會很多，用什麼樣的電等等，各式各樣的基礎設施整體就出現了。那當然，在這個新的AI科技社會體制中，我們的研究應該扮演什麼樣的角色，尤其研究倫理，還有一個什麼樣的新形態，這是我們從體制視野出發要問的問題。

從體制視野裡，我覺得有一個蠻精妙的提醒，對我們思考AI還蠻有用的一句話，這是在《監控資本主義時代》這本書裡——這是翻譯成中文的一本大書——它提醒了一件事：在過去還沒有AI介入的時代，科技介入比較早的時代，我們通常是坐下來開會，根據事實或公眾辯論，爭論說我們要以哪些價值、哪些角度做哪些選擇，應該做什麼、如何做，這是一整套的過程，在比較完整的公共論述或辯論裡面，大家是根據各種價值討論來做這些事。

但是，AI介入以後，慢慢傾向變成：因為AI很聰明，它「人工智慧」、它好像很客觀，它好像不會因為特定立場而做出某些判斷，所以我們有時候就會把剛剛那個討論的邏輯、爭論的過程，變成前面已經有一個既定的東西——根據特定資料訓練出來的AI的判斷，然後AI就可以建議可以做什麼，有點像你把你的研究資料丟進AI，它就告訴你答案，我比較簡化地這樣說。甚至，有些過程已經被壓縮到，在特定資料上訓練的AI，甚至已經結合了制度的決定，最後，問題只剩下「如何做」。

這個警告其實不是空穴來風，已經有蠻多書在談，現在——尤其在美國——很多社會福利、甚至監獄的監管裡面，都已經引入了某種程度的AI自動篩選、判斷資料，這個過程已經在發生，而且已經不是新聞了。

從體制的角度來說，這是一張從頭到尾串接起來的圖，是比較早期AI的訓練方式的幾個主要面向，我覺得放到今天，看代理型AI、大型語言模型，這幾個面向還是適用，可以看得很清楚。第一個是我們問什麼問題、設定什麼問題；第二個是根據這個問題，我們有哪些資料；第三個是這些資料有沒有被整體標註過——有一陣子，大概三、四年前吧，大家會說「人工智慧就是人工加智慧」，因為真的有一大群血汗工人，在標各式各樣的圖片，教AI怎麼看懂那個東西，現在也是一樣，很多人形機器人，也是用人去穿戴動作反應裝置，去教它怎麼拿一個杯子、怎麼抓一個東西、怎麼切一個蛋糕等等，這些都算是資料整理跟標註。然後再來是演算法的訓練跟調教，演算法有非常多種，調教成什麼樣子，再來到系統建置，最後到應用場域，這幾個面向都有很多學問。

在這邊我要強調，其實這兩年我比較在看AI這件事情，我之前的想法是，我們可以從比較簡單的幾個面向切入，就是「誰的問題、誰的資料、誰的演算法」這樣去看這些問題，但自從像ChatGPT這種通用型AI開始出現，尤其代理型AI開始出現的時候，我覺得這個問法可能要稍微調整。為什麼呢？因為在「問題」這個層面，現在已經開始出現各種因為有AI工具而被誘發出來的問題——海德格有一個寓言，說當你手上有一支鎚子的時候，你看什麼都像釘子，AI現在可能就是那支鎚子，大家可以看到，社群媒體或各式各樣的商業應用，現在什麼都要套上AI。

第二個是，AI污染資料的問題也非常大，據說去年——網路上有人統計——人類累積了幾十年、甚至前面幾個世紀的典籍資料都上網了，但短短一年多，生成式AI出現以後，它生出的資料量已經大於人類幾千年累積的資料量，所以這些資料都被污染了，如果重複拿這些被污染的資料去訓練，模型就會崩潰。所以有些公司開始去買一些古書，拿來掃描，因為怕被認定侵權，你可以買書來掃描，但不能直接把別人的資料輸進去，所以自己買的書就可以用，只是這樣一來，書也等於被毀了——這是AI發展中另外一個問題。

最後一個是演算法跟應用的競爭，現在已經出現一種「失速」的狀態，這些巨頭對於他們的應用，雖然大家都知道安全警告、人類的警告幾乎每一兩個禮拜、一兩個月就來一次，但沒有人願意停下來，因為停下來，萬一變成老二，人就輸了，這個世界就是這樣子，所以這件事情還蠻具體的：問題的問法不一樣，思考的角度也不一樣。

那要怎麼做呢？我自己再多觀察一下，給大家幾個經典的例子。這其實是很老的資料，2018年的資料，因為訓練資料的關係，造成誤判——譬如說左邊跟右邊，我直接講，左邊跟右邊都是婚禮，左邊是西式的婚禮，像白紗，右邊是印度的婚禮，但這是刊在《Nature》上的一篇文章，早年有一個模型被拿去訓練好以後，拿來辨識，它會說左邊是婚禮、右邊是變裝、是在演戲，它不會認為右邊也是婚禮。原因是什麼呢？這就是AI跟訓練資料重要性的問題，我覺得今天拿來重提還是有點意義，因為當AI看起來越來越無所不能的時候，它背後的資料到底是怎麼回事，這件事情可能會越來越難追溯，但它的影響反而會越來越深——就像中國的AI有些字是不能出現的一樣。

剛剛那個現象，原因是因為那時候大家常用來訓練AI的ImageNet這個資料庫，裡面有1400萬張已經標註好的影像，大家看一下，右邊紫色那一塊是美國，美國人口占世界人口4%，但它的資料量在裡面佔了45.4%；左邊是中國跟印度的資料，中國跟印度人口在全世界佔了36%，但資料量只佔3%，這就是AI誤判的原因之一。這件事情放到今天大型語言模型的角度來說，以台灣的角度來想，像繁體中文、甚至台灣客家人、原住民族，不同族群的思想化為文字，有多少進入了大型語言模型裡面？這也是台灣現在推動台灣AI計畫，持續努力、也已經努力了一陣子的方向。

所以在這個意義下，如果從體制的角度來看，剛剛英國皇家學會那句話或許就有點道理：他們意識到，在AI的時代，問題可能不再只是學科的講法或學科理念，而是要從公眾利益的角度來想。那是哪一種公眾利益呢？譬如說，我就用現在常見的SDGs——全球永續發展目標——來說，如果我們把學科、AI、跟這三者連在一起看，我們可以從體制層面回應這些問題，這是一種思考方式，那我們需要哪些倫理規範呢？

在這個意義下，我就舉一個例子，譬如SDGs第十項裡面，「減少國內及國家間的不平等」這個議題，這件事其實一直存在，尤其是從殖民主義以後，這種不平等被大幅拉大，怎麼樣稍微拉平一點、讓它好一點，這件事其實全世界都有共識，但怎麼做，各種方法都還在爭論。在AI的時代，這樣的不平等狀況，我們可以看到其實更加明顯、更加嚴重。當然，這些專利數字只能代表AI能力的一部分，實際狀況我們不完全清楚，因為看起來中國的AI專利數量是最多的之一，但前陣子也大概知道，中國的很多AI是從現有的美國AI裡面提煉出來的，這個數字是否能夠如實反映現況，是另外一件事，但至少在大趨勢上，我們可以看到AI帶來的這些不平等基本上是被加劇的。

另外一個是，世界各國對於研究工具、研究整體面向的各種國際質疑也還蠻多的，細節我就不多說了，我想介紹的是，去年底在《科技、醫療與社會》期刊的第11期，我們做了一點小小的討論，大家有興趣的話，針對這些國際上已經累積很多的、各式各樣的質疑敘事，可以去看一下。裡面有一篇文章——原逐字稿作者姓名聽辨不清（逐字稿作「專長老師」）——是從研究人員、機構等等，和「概念建構」這個角度，還蠻完整地把這些議題整理過一遍。

最後一個，如果我們從時代革命的視野來看AI，可以看到，這張圖也是跟王道維老師一起討論出來的：從第一次工業革命，到第二次泰勒主義，第三次資訊革命，到第四次現在的物聯網、AI等等，這看起來是一個新的工業革命，對我們、或現在正在成長的下一代來說，信不信，我們正遇上這一波正在進行中的新工業革命。對這場工業革命中AI研究體制的問題，我有一些小小的想法，不過那是另外一場演講的內容了，所以就請大家參考，我從一個新的面向去看這件事。

但今天我希望跟大家分享的是另外一個議題：如果我們把AI視為一個新的工業革命、新的科技革命，它對全世界帶來的轉變是很大的，也常常被低估。大家可以想像工業革命之前跟之後的差異，那研究規範在其中，可以像是一種很重要的全球執行基礎設施。在這種大量變動的革命當中，我們要怎麼去想像它呢？這是一件很困難的事。

現在關於能不能在論文裡引用AI生成的成果，其實有些期刊已經規定哪些部分可以用、哪些不能用，就我自己的想法，用了就誠實揭露會比較好，因為到最後，如果規定不能用，你就不要用，這是目前各家規範還不一致時最好的做法，但我知道很多期刊已經說明哪些部分是可以用的，例如你可以用AI來翻譯、檢查字詞，這是可以的，但不能用它來生成內文。另外跟大家說一個訊息：現在很多AI生成的文字裡面有「浮水印」，不是我們一般理解的那種浮水印，而是某種類似的標記，未來在偵測AI文字的時候可以被檢測出來，因為現在光靠文字風格去判斷是不是AI生成，已經變得非常困難了。譬如珍．奧斯汀（Jane Austen），大家知道她是很有名的浪漫史小說家，她的文字如果丟到AI偵測工具裡，AI會判斷有百分之九十是AI生成的文字，因為她的文字裡有大量重複、類似的語句，那剛好是AI學習後容易產生的一種標準文字風格——因為AI是學她的文字風格學來的，結果反而被誤判。還有一個案例，紐約大學有個學生交了論文，學校偵測後認為是AI生成，不給他學位，他就告學校，結果學校沒辦法正當地證明他真的是用AI寫的，所以他上訴成功。這件事情就說明這條路還很輔助性、還不成熟。所以在這個過程中，如果有明文規定不能做，那就不要做；如果沒有明文規定，誠實引註還是最好的做法。最後歡迎大家填一下我們的問卷，因為問卷設計得很用心，你對於這些不同層次的問題會有更清楚的想法，最後的結果我不會公布個人數據，但填答的量要多一點我們才會整體公布，不然只有一點點意見沒辦法呈現。謝謝大家。

王道維老師還放了一張學生第一學期跟第二學期排名對照圖，作為「這件事可能有效」的具體證據（本文只轉述他口頭描述的圖表意義，沒有看到原始投影片可交叉核對細節）：使用小泰特別多、互動性也比較高的學生，排名多半是提升的；用得比較少的學生，排名往後掉；而且提升幅度最大的是中段學生，因為前段學生本來就沒什麼提升空間了。

04 — 「讀伴」的設計理念：一張學生看不到的地圖

「讀伴」的設計理念：一張學生看不到的地圖

「讀伴」是王道維老師團隊做給人社領域的AI助教，核心不是給答案或做摘要，而是陪伴閱讀的過程。它的第一個關鍵設計，是把學生跟AI之間的對話「攔下來」加工，再靠社會科學院院長引入的Hayden White meta-history架構，先把文字拆解成一張學生看不到的地圖。

逐字稿原話
學生在使用的時候，透過他的終端裝置到AI之間，我們把它先攔下來，他寫的東西，我們經過一些處理，再傳回到AI；AI給我們東西，我們再處理，再給學生。所以學生看到的，不是原始AI回覆他的問題。

王道維老師特別澄清「manipulate（操縱）」這個字不是竄改學生講的話，而是在系統層加東西：

逐字稿原話
「manipulate」不是說改他講的話，而是說加了一些system prompt——就是一些隱藏在系統裡面的設計——讓學生得到的結果不是AI原始的結果，而是經過一些架構處理過的。

這個「架構」具體是什麼？王道維老師說，這是社會科學院院長最重要的貢獻——引入海登・懷特（Hayden White，round2校對依歷史哲學脈絡修正自逐字稿ASR的「Hyton White」）的「meta-history」概念，把文字拆成四層分析：

逐字稿原話
它基本上有四層：從修辭、〔形式〕、論證，到意識形態，我想各位搞不好比我還清楚。

「形式」一詞round2校對標記為聽打不確定（原ASR作「形結」），也考慮過「情節」（呼應Hayden White《Metahistory》原有的emplotment一項）這個替代猜測，但因這場沒有投影片可核對，兩種猜測都未能確認，本文如實保留這個不確定性，不逕自替換成任何一種。

關鍵是：這四層分析的結果，不會直接顯示給學生看。

逐字稿原話
分析的結果不會告訴學生，它是隱藏的。這樣可以確保，學生跟AI互動的時候，是有一個足夠、可控的核心內涵去做對話，而不是靠AI原始的、那種語言模型原始的文字接龍能力來對話。

同一篇文字，團隊還會同時從文學、史學、哲學、社會學四個角度，讓四個agent分別分析，整理進AI內部——王道維老師稱這是要對應人社領域「同一件事可以從不同角度來看」的特性。如果搭配課程使用，老師甚至可以直接修正AI對這篇文字的分析：

逐字稿原話
老師可以看到這個AI怎麼去分析這篇文字，如果有必要的話，老師可以去修正它——不是AI修正它，是老師可以去修正它，說「你這個分析還有點不到位，我再補充一點」，這是可能的。
05 — 讀伴怎麼陪你讀：三種角色與可以長出去的對話

讀伴怎麼陪你讀：三種角色與可以長出去的對話

有了隱藏的地圖之後，讀伴用三種角色陪學生對話，而且對話不是一路往下的直線，可以像樹枝一樣分岔出去、再收回來。現場也用兩分鐘demo了整個流程。

引導者
預設角色（round2校對推測，原ASR作「D4」，未能完全確認）
「引導者」就是引導他
批判者
提供另一個觀點，讓學生跟它辯論
站在另一個領域提出comment
探索者
學生卡住時，給另一個角度想想看
學生可自行切換角色

王道維老師特別展開講了「批判者」這個角色怎麼運作：

批判者這時候可以跳出來，說這篇文字搞不好還有另外一個角度的看法、另外一些學派，用不同的深度或不同領域的角度來看，然後站在另一個領域提出另外一個comment，這時候學生就要跟它做對話，這樣學生才會發現：「原來這件事情還有另外一種想法」，是他以前不知道的。

王道維老師也拿讀伴跟一般AI對比：一般AI會被使用者話題帶著跑（他舉的例子是學生聊到一半突然說「我家裡有什麼事」、「我女朋友怎麼樣」），但讀伴不會：

逐字稿原話
而且我們這個讀伴是不會這樣的，它就focus在這篇文字上面去談，所以它不會被拉走，因為它有一個核心，這和一般的語言模型不一樣。

這句話前一句原ASR作「但是我們的小太太」，語意不通，round2校對推測可能是「讀伴」的重複或口誤但無法確認，本文只採用語意清楚、無爭議的後半句。

「非線性分支對話」是院長很重要的貢獻——學生不必照直線一路談下去，可以隨時分岔：

逐字稿原話
我想要一個主題，我想分支出去，然後在那個地方繼續談，談完之後，如果覺得蠻有價值就留在那裡，或者覺得沒有價值就把它刪掉，或者可以把它接回來，然後可以再分支、再分支，有三層可以分支出去。

現場demo兩分鐘裡，王道維老師實際展示了這個分支怎麼長出來：

逐字稿原話（現場demo）
所以你看，「節外生枝」就出來了，這就是主幹，生出來，你可以再生，每一個生出來你可以繼續對話，然後可以選擇——所以它等於同時有好幾組對話平行進行。你看，畫一條線，它就會變成一個筆記，就有點像筆記的功能。

最後王道維老師強調，讀伴最後產生的摘要跟一般AI摘要不一樣——它摘的不是那篇文字，而是學生自己跟AI談出來的東西：

逐字稿原話
它摘要的是學生跟AI所講的話，和學生認為重要的東西，所以每個學生寫下來的都會是不一樣的東西，它不是在摘要那篇文字——那篇文字大家摘要出來都會是一樣的東西——每個人講的東西是不一樣的。
06 — 學生的第一手經驗：楊奕恩讀《莊子・逍遙遊》的一百輪對話

學生的第一手經驗：楊奕恩讀《莊子・逍遙遊》的一百輪對話

外語系學生楊奕恩親自上台，示範她怎麼用讀伴重讀《莊子・逍遙遊》。她講清楚了一件事：這不是一兩次對話就有結論，而是大約一百輪，而且是拿她之前修課的期末報告結論，去跟這次跟讀伴對話的結果對照。

逐字稿原話
那我這次會透過我之前修過課的期末報告的結論，跟近期與讀伴對話的結果去做分析，那我的對話也大概進行了一百輪左右，所以不是單純一兩次對話就得出的結果。

她從《莊子》原有的「小大之辨」切入，一開始的想法是鯤鵬形象巨大，象徵無限的自由；讀伴馬上反問她：

逐字稿原話
一開始我是從「小大之辨」這個概念去切入的。我一開始的想法是，覺得鯤鵬的形象巨大，象徵無限的可能性和自由，我就把這個想法當作切入點丟到讀伴的對話裡面，它就開始挑戰我的想法，說：「可是鵬鳥需要風、需要積水，這些條件還有時機，這樣還算是無限的自由嗎？」

對話一路往下，讀伴又逼她面對「至人無己」這個更難的概念：

逐字稿原話
它引導我說：「莊子心目中最後一步的『至人無己』的『無己』是什麼意思？連自我判斷這件事本身也要放下嗎？」然後我就說：「會不會是沒有對自己的成見呢？」接下來我們又討論到，「小」和「大」到底是誰去決定的？

這場最值得一提的一段，是楊奕恩在對話中提到老子「聞道」的說法。round2校對第二輪重新聽打、並對照《道德經》第四十一章原文「上士聞道，勤而行之……下士聞道，大笑之，不笑不足以為道」，判斷這是一句被誤聽的引用（ASR原本聽成「情而行之」「大孝之」）——這是round2校對信心程度較高的推論，但因這場沒有投影片可交叉核對逐字用字，仍不是百分之百確定的逐字稿內容，這裡如實標明：

逐字稿原話＋校對推論（信心程度較高，非百分之百確定）
我就問它，「條」中的效果會不會像是老子所說的『聞道，勤而行之』呢？像是聞道『大笑之』的感覺呢？它說：『你這個想法很不錯，那你會不會覺得，「條」中的效，是不是也是一種以為自己懂了的觀點？』

楊奕恩接著自己的反思，是這一段裡最有意思的地方——她意識到自己可能正落入讀伴剛剛描述的那個狀態：以為自己懂了，其實只是另一種「條」中（round2校對查證，「條」應為讀伴系統中「分支對話」的口語簡稱）：

逐字稿原話
我就突然恍然大悟，好像我某方面也覺得自己已經懂了，所以我是不是某方面也成為了「條」中呢？

最後她把這次的過程，跟自己原本期末報告的結論做了對照：

逐字稿原話
相較於我最後——原本期末報告的結論只有強調，真正的智慧在於能夠超越這些相對的界線，達到一種逍遙無拘無束的境界，是比較籠統的結論。……它不會直接跟我講答案，它會一步一步引導我去整理自己的想法，然後最後可以收束成屬於我自己對文字的理解。

誠實說明：逐字稿裡還有兩處她引用的段落（討論宋榮子「猶有未樹」處、以及最後一條分支的收尾句），round2兩輪校對都判斷聽打語意不明、無法確認正確原詞，也無法在《莊子》原文找到逐字對應，本節依比喻紀律與grounding紀律，刻意沒有把這兩處當成確定的引用素材寫進來。

07 — 教師端看到什麼、能不能推廣、還留下什麼問題

教師端看到什麼、能不能推廣、還留下什麼問題

最後王道維老師回到教師端功能、他自己對「隱私疑慮」的直接回應、跟教育部或學校合作推廣的構想，以及這個系統目前自己承認的侷限。這節也把幾個沒被完全解決的問題誠實列出來。

老師端可以看到學生跟讀伴談了什麼，也可以事後把AI建立的「地圖」攤出來對照——王道維老師舉的例子是他上傳司馬遷〈貨殖列傳〉（他形容原文約十頁左右，是李老師提供的教材）：

逐字稿原話
如果我是老師的話，我上課之後會把學生講的東西和這個地圖攤出來讓學生看，看看你們講了半天，跟這個地圖相比差多少，他就會知道自己現在了解的這麼少，那這樣的話，當然他們願意的話，可以想辦法再多做一點。

現場有人（或王道維老師自問自答）提到隱私疑慮，他當場直接給出自己的立場，本文原樣轉述，不代為評論：

逐字稿原話（講者自己的立場，非逐字稿裡的辯論結果）
那你說這會不會牽涉到隱私？這哪有什麼隱私，這就是學習工具嘛，這不是來跟你談你自己個人的事情，我要了解你的學習過程，這有什麼問題呢？

王道維老師也主動講了系統目前的侷限，適用對象比較侷限在大學部：

逐字稿原話
最好的可能是在大學部——這個中低年級這一段，可能在建立基礎上面會有所幫助；到研究生的話，也許程度就可能不夠，因為研究生搞不好會讀論文，會有些更特別的看法，可能不是我們現在的AI能夠完全掌握到，而且這也是有可能的。

他也把讀伴跟一般語言模型直接比較，講清楚讀伴要解決的問題是什麼：

逐字稿原話
如果你用一般的LM，基本上很有效率地讀完，這是為什麼學生喜歡它，因為他覺得不用浪費時間，它提供了某種標準答案。但實際上它的缺點就是，學生沒有經歷這個消化的過程，甚至簡單來說，學生根本沒有讀文章，他就叫AI讀，根本沒有在自己讀。

對於推廣，王道維老師的構想不是每個老師各自打造一套系統，而是幾個老師合作、由學校或教育部支持，做出不只一套AI讓大家挑：

逐字稿原話
我們可以說，例如歷史學門、人社學門，有幾個老師一起來研究，然後假設教育部或學校來做一些……弄出一個不錯的AI，大家一起分享，甚至不會只有一個，除非有兩三個，然後大家看哪一個比較好用，你有你自己的理論、你有你自己的設計，這個比較好用，我可能就用這個。……我們一定要把AI當成一個工具，而不是把它當成敵人。

王道維老師提到這學期會在「新大哲學院」試用（原文逐字如此）——round2兩輪校對都無法從逐字稿本身確認這個機構名稱，第一輪曾猜測是「成大」並附註「講者任教於成功大學」，但這個理由在整份逐字稿裡找不到任何依據，本文如實保留原始ASR文字，機構名稱請楊老師依對講者背景的實際認識自行核對。

誠實標記：這場逐字稿沒有正面回答的問題——讀伴的「地圖」對學生是完全隱藏的（見第4節），王道維老師講的是這樣能確保對話「有足夠可控的核心內涵」；但地圖本身是老師與AI事先框定的一套分析（Hayden White四層架構＋四領域agent），學生走進去的路徑再自由，終究是在這張預先畫好的地圖裡走。這張地圖究竟是在打開學生的多元詮釋空間，還是預先框定了一種被認可的詮釋方向？逐字稿裡沒有任何一段正面討論這個張力，王道維老師也沒有被問到這一點——這不是他沒回答好，而是這場演講本身沒有觸及，本文不代為填補答案。同樣地，「隱私會不會是問題」也是王道維老師自己給出的立場、當場沒有被追問挑戰，讀者可以自行判斷是否認同。
