0. 範例資料下載連結（投影片QR碼／縮短連結） 
https://reurl.cc/bedGvd

點開後有五個資料夾：明天要用的CodeLab AI原理教學程式、老師自己寫的AI Agent skill程式框架、 兩天課程所有簡報、範例史料（含Markdown筆記檔案），以及安裝檔。現場也有助教發USB， 老師說「USB是最快的」。

1. 下載 Obsidian 
https://obsidian.md/
老師選Obsidian的三個理由（逐字稿原話整理）：它免費、不用錢；它用Markdown格式儲存， 是純文字檔，跟現在AI的腳本大多也用Markdown寫剛好接得上；最關鍵的是「你的筆記不是存在服務商的雲端， 而是存在自己的電腦裡面……它只是一個閱讀的工具而已」——資料留在本地端，不會因此外洩。
2. 建立筆記儲存庫，選好存放位置

取一個名字（老師舉例：會議名稱、或「張哲維的筆記」都可以），按「瀏覽」選位置—— 可以放桌面、放USB隨身碟（筆記跟著硬碟走，比較不容易不見），或放Google雲端硬碟。 老師順口提了一句：「所有的資料備份要3-2-1，就是必須要有三份備份、兩種介質，這很重要喔」。 Google雲端硬碟路徑設定因為時間有限，老師直接說「大家回去自己看PPT」，現場沒有展開。

3. 註冊 Hugging Face

投影片標題直接寫「開源模型託管網站」——老師形容它是「模型界的Github、提供雲端算力」， 免費算力雖然不多，但教學使用沒問題。註冊完一定要回到信箱按「開通」， 老師特別提醒「我們通常教學的時候，有時候遇到問題就是因為沒有按開通」。 老師也順口提了一個時事：「前幾天9月3號的時候，NVIDIA宣布以130億美元收購Hugging Face這個平台， 並且承諾維持開放」——這是老師課堂上講的內容，供參考。

4. 安裝 ChatGPT 桌面版

從ChatGPT網頁版右上角「工作」選單裡的「開啟桌面應用程式」進入下載， 依系統（Windows／Mac）自動抓對應版本。

5. 把 Obsidian 筆記資料夾接進 ChatGPT「專案」

滑鼠移到「專案」旁邊會出現一個小加號，點下去建立專案、選「加資料夾」， 指向剛剛用Obsidian建立的那個筆記庫資料夾——「這樣的話，你在Obsidian裡面做的所有東西， 都有辦法在AI裡面讀到，然後幫你進一步處理」。這是第一場最後、也是整個安裝流程真正收尾的一步。

01 — 歷史學何以成為科學

從笛卡爾到新康德主義，四位哲學家一路推出來的四點邏輯

這是第一場份量最重的一段（投影片p59-68）——老師說自己「花了蠻多時間讀他們的原典去統合起來」， 是整場唯一一段接近純哲學史鋪陳的內容。

笛卡爾提出「科學萬能論」，偏向數理化的科學方法， 強調邏輯、統整、量化統計
→
維柯義大利哲學家，提出除了數理化科學方法之外， 應該還有一種「詩性的邏輯」——不是萬事萬物都能純粹客觀地用數據解釋
→
康德認為只有數學跟哲學才具有「絕對的科學性」， 其餘學科（物理、化學、生物……）都只是基於某種假設前提推演出來的「相對的科學性」
→
新康德主義四子狄泰爾、文德爾班、李凱爾特、卡西勒， 以「回到康德」的口號，維護人文科學的獨特性

人文科學的研究邏輯，四點

A

研究對象的個別性。老師舉的例子：如果按自然科學邏輯，要有一千個蔣介石， 統計分析之後跑出來的數據才叫「蔣介石」；但全世界只有一個蔣介石， 人文研究對象都是個別的，不可能重複出現。

B

研究者的自身經驗。我們必然透過自己的經驗跟文化脈絡去解釋過去。

逐字稿舉例
「我們對於『民主』這個概念的想法，台灣可能跟中國大陸就不太一樣…… 我們看到中國大陸寫『民主』這兩個字，跟台灣人寫的雖然是同樣兩個字，它的核心概念一定不同。」
C

意義來自共鳴、來自連結。老師舉自己的研究：因為做近代史， 看到跟自己研究時代相近的東西（例如「楊瑞珍老師的研究」）就更有連結、更有意義； 但這不代表沒連結就沒意義，只是對個人來講的意義不同——老師自己說對荷蘭時代台灣史接觸就比較少。

D

主客合一的客觀精神。人文研究追求的不是一個純粹客觀的東西， 而是主觀涉入之後的客觀見證——「人文科學本來就不是資料的堆砌，也不是模型的分析， 這跟AI的根本原理是有很大不同的」。

老師接著補了一段對後現代批判的看法，自己形容是「張飛打岳飛」——他認為後現代批判從來不是在批判 探究歷史事實的歷史學本身，而是批判自黑格爾哲學以來對單一主體性的霸權宰制；基於史料辯證為前提的歷史學， 本身就具有科學性，「如果基於史料辯證為前提的歷史學不被認為是科學的話，那麼從康德的視角來看， 從物理學以降的所有科學，都不具備科學性了」。

傅斯年〈中央研究院歷史語言研究所工作之旨趣〉（1928年，投影片原文）： 「史學只是史料學」「讓史料自己說話」，利用社會科學理論和方法來處理史料—— 老師由此主張歷史學的科學性根本，落在史料的可驗證性、可追溯性、可糾錯性三點上 （投影片p68三詞原文）。
02 — 電腦與人

電腦的本質，以及AI取代不了的三件事

投影片p74是一張人與電腦的對照表，老師直接照著唸過一遍，這是整場唯一一張現成表格。

項目人電腦
記憶量小趨近於無限
運算速度慢快
疲勞會累不會累
情緒愛鬧脾氣不會鬧脾氣
出錯會出錯不會出錯
思考會思考 ✓不會思考 ✗

運算流程（投影片p71）：問題 → 拆解成複雜數學運算 → 拆解成簡單數學運算 → 二進位運算 → 交給邏輯單元運算，再反向推演出答案。老師的結語：「它展現出來的看似人一般的智慧， 其實都是用計算模擬出來的結果」「只要有辦法跟電腦溝通，電腦就是反過來，從邏輯單元的運算， 一步一步推演出去，最後給你答案」。

靈感與創見AI只會在自己的運算框架裡繞，突破只能由人給的新資料、新想法帶來
共鳴寫作如何跟別人產生共情，這件事AI做不到
脈絡化理解從個人自己出發去理解一個文本、再轉譯給當代的人， 這是電腦沒有辦法做的事
老師的樂觀論點：「AI反而是人文再興的一個可能」——過去要花十幾萬找工讀生寫網頁前端， 或投入大量時間精力做一款歷史遊戲，「現在不用了……只要把自己的想法描述出來，它就可以變成一款簡單的歷史遊戲」； 但老師也點出反面：資工的人拿到我們的東西變簡單了，「他們要理解我們，還是一樣困難」—— 人文因此反而變得更重要，「但最重要的東西還是思考，就是思考」。

01 — 從手稿到一則筆記

史料進到 Obsidian 的實際流程

投影片第58-88頁示範的實際操作順序——這不是抽象講法， 是他真的一步步點給大家看的動作。

1. 新增「手稿解讀」資料匣，把手稿資料匣拖拉進去

先建立容器，再把原始材料放進來——資料夾結構本身就是第一層分類。

2. 在資料匣中新增新筆記，為筆記命名

一則筆記對應一份史料（或史料的一個段落），命名要能讓自己半年後還認得。

3. 筆記第一行寫 ---，開啟YAML區

這是「正文前頁」，專門用來賦予這則筆記元資料（Metadata）—— 人事時地物、出處、建檔人都寫在這裡，不混進正文。

4. YAML區裡也能用 [[ ]] 連結其他筆記，再賦予同義字

同一個人事物在不同史料裡可能有不同寫法，同義字讓搜尋/鏈結不會斷掉。

5. 用 Transkribus 或直接用 ChatGPT 做手稿辨識

Transkribus 底層是卷積神經網絡（CNN），專門辨識手寫古文書； ChatGPT 則是直接把手稿影像丟進去問。兩條路都示範過。

6. 「請根據你的判斷修改成正確的文章」——人工校對AI辨識結果

AI辨識不是終點，最後一定要人核對過——這句話是投影片原句， 是這整套流程裡唯一「不能交給AI」的一步。

02 — 真實範例：兩種YAML元資料

同樣是「正文前頁YAML區」，用途不同、欄位設計就不同

哲維老師課程成果〈1954年台灣醫師名鑑〉是學生逐筆手key的真實筆記， 水經注則是他整理古籍用的另一套欄位——兩份都是他教材裡真正的檔案，不是示範用假資料。

吳新榮.md

1954年台灣醫師名鑑課程成果 · 建檔人：112-2第七組 林毓馨

傳記／表格型 
籍貫: "臺灣省"
性別: "男"
出生年: 1907
出生地: "臺南縣"
畢業學校: "東京醫學專門學校"
經歷: "臺南縣參議員 臺灣省醫師公會理事"
經度: "120.17648462142948"
緯度: "23.16059326236851"
出處: "1954年臺灣醫師名鑑，241"

每個欄位都是固定的「屬性」——經緯度甚至能直接餵進GIS地圖， 這種YAML之後最容易整批轉成表格/資料庫。

水經注.md

酈道元，西元515-524年間 · 哲維老師整理

古籍／文獻型 
作者: "[[酈道元]]"
出版年: "[[西元515年至524年間]]"
整理底本: "維基文庫水經注繁體版"
校核參考: "中國哲學書電子化計劃；
  Kanripo KR2k0058水經注"
標注方式: "一級標題標示原序與卷次"

注意「作者」「出版年」欄位本身就用[[ ]] 雙向鏈結——連元資料欄位裡都能鏈結，這是表格型YAML做不到的彈性。

04 — 卡片盒筆記法（盧曼 Zettelkasten）

四層筆記，從靈感到一篇完整文章

這是整場投影片份量最重的一段（p108-146）——把史料解讀的想法， 一步步沉澱成能寫進論文的完整論證。

每日筆記每日靈感紀錄，最原始、最零碎
→
文獻筆記史料解讀／文書筆記／元資料， 讀一手或二手材料時的想法
→
永久筆記凝聚出的具體想法， 用自己的話寫、不是抄
→
專案筆記寫文章前的內容安排， 定期審視永久筆記後確定題目

寫「永久筆記」的三個原則

A

用自己的話寫，不要抄。每一則永久筆記都以最精簡的方式寫到最完整的短文。 如有引用，用雙向鏈結跟文獻筆記連在一起，不是複製貼上。

B

思考與其他永久筆記的關聯性，用編號體系記下脈絡——這是樹枝狀的體系， 不是流水帳。

投影片p133原例
1. 我中午要吃什麼好呢？
1.1 我想吃炒麵　　1.1a 炒麵要吃沙茶口味（1.1的延伸）
1.2 或者可以吃炒飯（1.1和1.2是平行關係，都在探討同一個上層主題）
C

每次寫卡片都要前後左右看一看，就能知道之前思考的脈絡是什麼—— 永久筆記不是孤立存在，寫的當下就在跟舊筆記對話。

05 — 從永久筆記到一篇學術文章

學術文章的每個部件，都對應一種筆記

確定題目後進到「專案筆記」構思大綱——哲維老師把論文結構直接對應回 卡片盒筆記法的產物，這個對照表是投影片p139的核心。

題目= 專案筆記之名稱
=
專案筆記定期審視永久筆記後確定的研究主題
關鍵字= 核心論點＝貫穿全文的主軸
=
永久筆記的編號主幹樹枝狀體系裡最上層的「1.」那條線
各章節內容= 連結與之相關的筆記
=
永久筆記的分支1.1／1.2／1.1a 這些延伸主題各自展開
引用文獻= 文獻筆記
=
史料解讀筆記回頭核對出處，引用要有所本
AI輔助生成的具體做法（投影片原話）：綱要＝文章的推論過程（線性）、摘要＝關鍵字＋綱要， 整理好這些之後丟給ChatGPT／Gemini協助書寫——建議先餵給它整份專案筆記，再逐章生成， 生成結果貼回Obsidian，最後「引用要有所本→文獻or史料」「請參照一般論文格式」—— 這兩句是投影片對AI輔助寫作僅有的兩條紅線。
